# Как залить этот пакет в репозиторий (2 минуты)

> **Пакет уже применён** (ветка `arena/01a0ec40-settled-lands`, PR #2), поэтому
> заливать его повторно не нужно. Инструкция ниже оставлена на случай, если файлы
> всё-таки правились через сайт и их надо вернуть.

Внутри четыре файла, они **заменяют** уже существующие:

```
.github/workflows/build.yml     — сборка и 36 unit-тестов
.github/workflows/smoke.yml     — серверный набор, 117 проверок (119 при повторе)
tools/static-check.py           — статические проверки (теперь без падений с трейсбеком)
GITHUB.md                       — описание проверок, дополнено результатами
```

## Способ 1: перетащить (быстрый)

1. Распакуйте архив в любую папку.
2. Откройте страницу загрузки:
   <https://github.com/BORGERone/Settled-Lands/upload/main>
3. Откройте распакованную папку и перетащите в окно браузера **три элемента**:
   папку `.github`, папку `tools` и файл `GITHUB.md`.
   Перетаскивайте именно элементы внутри папки, а не саму папку архива —
   иначе пути получатся вида `пакет/.github/...` и файлы лягут не туда.
4. Внизу страницы нажмите **Commit changes**.

## Способ 2: руками (если браузер откажется брать папку с точкой)

Сам `.github` перетаскиванием иногда не берётся. Тогда откройте файлы по ссылкам и
замените содержимое целиком (Ctrl+A, затем вставить из распакованного пакета):

- <https://github.com/BORGERone/Settled-Lands/edit/main/.github/workflows/build.yml>
- <https://github.com/BORGERone/Settled-Lands/edit/main/.github/workflows/smoke.yml>
- <https://github.com/BORGERone/Settled-Lands/edit/main/tools/static-check.py>
- <https://github.com/BORGERone/Settled-Lands/edit/main/GITHUB.md>

## Что изменилось

- действия обновлены на `v5` (предупреждения про устаревший Node.js 20 исчезнут);
- система закреплена как `ubuntu-24.04`;
- после сборки в сводку прогона печатается **размер и sha256 собранного JAR** —
  так результат можно проверить, а не принимать на слово;
- отдельный шаг сравнивает собранный JAR с тем, что лежит в репозитории, и честно
  пишет в сводку «совпадает» или «отличается» (расхождение не роняет сборку);
- статические проверки больше не падают с трейсбеком, если файла ещё нет в
  репозитории: они пишут понятное сообщение, а отсутствие `smoke.yml` — только
  замечание, а не ошибка.

## После загрузки

Появится новый прогон **Actions → Build**. Зелёная галочка = всё в порядке:
статические проверки, сборка, 36 тестов. В сводке прогона будут отпечатки JAR.

Серверный набор (117 проверок) сам не запустится: он срабатывает только при
изменении `src/**` или вручную — **Actions → Integration suite → Run workflow**.
