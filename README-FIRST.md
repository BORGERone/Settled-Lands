# Что делать с этим архивом (5 минут)

В архиве **только те файлы, которых нет в репозитории** `BORGERone/Settled-Lands`,
или их обновлённые версии. Готовый мод, исходники и остальная документация уже залиты —
их повторно загружать не нужно.

Причина, по которой пакет вообще понадобился: браузер при перетаскивании файлов
**не загружает папки и файлы, начинающиеся с точки** (`.github`, `.gitignore`).
Поэтому в репозитории нет `.github/workflows/` — и GitHub Actions не запускаются
вообще, то есть автоматических проверок сейчас нет.

---

## Шаг 1. Файлы с точкой — только вручную

Для каждого пункта: в репозитории **Add file → Create new file**, в поле имени вписать
путь целиком (слэши создают папки), вставить содержимое файла из архива, **Commit changes**.

1. `.github/workflows/build.yml` — сборка и 36 unit-тестов на каждый push.
2. `.github/workflows/smoke.yml` — 117 интеграционных проверок на настоящем сервере.
3. `.gitignore` — чтобы `build/`, `.gradle/` и `run-smoke/` не попали в репозиторий.
4. `.gitattributes` — нормальные переводы строк для генератора.

После первого пункта в репозитории появится папка `.github`, и вкладка **Actions**
оживёт.

## Шаг 2. Обычные файлы — можно перетащить

**Add file → Upload files**, перетащить:

- `docs/TESTING-HOWTO-RU.md` — как устроены тесты проекта (можно передавать другому ИИ);
- `tools/static-check.py` — проверки без Java и без запуска игры;
- `scripts/setup-toolchain.sh` — ставит JDK 21 там, где Java нет;
- `scripts/verify-all.sh` — полная проверка одной командой;
- `README.md` и `GITHUB.md` — обновлённые версии, перезапишут старые.

## Шаг 3. Проверить, что проверки работают

1. Вкладка **Actions** → workflow **Build** запустится сам после коммита.
   - зелёная галочка: сборка и 36 unit-тестов прошли;
   - артефакт `settledlands-jar` в конце страницы запуска — это собранный мод.
2. Workflow **Integration suite** → **Run workflow** (вручную; он тяжёлый).
   - зелёная галочка означает, что прошли все **117** проверок на живом сервере;
   - в артефакте `smoke-log` лежит журнал со строками `CHECK OK`.
3. Красный крест — откройте упавший шаг: в конце будет причина. Для серверного набора
   ищите `SANCTITY SMOKE FAILED` и текст ошибки под ней.

## Почему это важно для проверки работы другого ИИ

У ИИ в песочнице обычно **нет Java и нет сети**, поэтому он физически не может собрать
проект и запустить сервер. Теперь это делает GitHub: ИИ заливает ветку — Actions собирает
и прогоняет проверки — вы видите результат. Если он утверждает, что код работает,
у этого утверждения появляется проверяемое подтверждение.

## Локальная проверка (если понадобится)

```bash
source scripts/setup-toolchain.sh      # поставит JDK 21 в /tmp/tools/jdk21
scripts/verify-all.sh                  # статический анализ + сборка + серверный набор
SKIP_SMOKE=1 scripts/verify-all.sh     # то же, но без запуска сервера
```
