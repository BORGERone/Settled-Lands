**Minecraft 1.21.1 · NeoForge 21.1.252 · Java 21 · версия 0.4.4 (альфа)**

Игроки постепенно подавляют естественное появление монстров. Обустроенные места
могут стать безопасными навсегда; необустроенные маршруты со временем снова дичают.
Мод не заменяет воздух служебными блоками и не удаляет уже существующих мобов.

## Установка

1. Сделайте резервную копию мира. Первую проверку проводите на отдельном тестовом сервере.
2. Установите **NeoForge 21.1.252** для Minecraft **1.21.1**, Java **21**.
3. Поместите `settledlands-0.4.4.jar` в серверную папку `mods/`.
4. Для полноценной подсветки установите **этот же JAR** на NeoForge-клиент администратора.
   Обычным игрокам мод на клиенте не требуется: сетевой канал зарегистрирован как необязательный.
5. На этой версии NeoForge конфиг по умолчанию создаётся в
   `config/settledlands-server.toml`. Для отдельных настроек мира можно заранее
   разместить файл в `world/serverconfig/settledlands-server.toml`: он используется
   как переопределение. Меняйте настройки при остановленном сервере.

Этот мод не предназначен для Fabric, Forge или Bukkit/Paper.

## Механика по умолчанию

### Ячейки и убийства

- Фиксированная сетка **16 × 8 × 16** (X × Y × Z), отдельно в каждом измерении.
- Учитывается положение ног моба. Поверхность не зачищает всю вертикальную колонну.
- Стены и перекрытия внутри одной ячейки не разделяют защиту.
- Зачётное убийство даёт `+1` временной зачистки и `+1` постоянного прогресса
  каждой из **3 × 3** ячеек в горизонтальном слое вокруг смерти.
- Кроме того, `+1` получает исходная ячейка естественного появления моба.
- Если исходная ячейка уже входит в область смерти, повторного начисления нет.
- Убийство в постоянной зоне всё равно помогает непостоянному источнику и соседям.
- При превращении через `LivingConversionEvent.Post` метка происхождения переносится.

В зачёте используется смертельный источник игрока **или** ванильное недавнее участие
игрока (`lastHurtByPlayerTime > 0` и игрок-участник). Поэтому смерть от падения вскоре
после удара может считаться. Ванильный зачёт может включать действия приручённых животных.
Опыт не подсчитывается; `/kill` без участия игрока не является способом тестировать зачистку.

### Какие мобы участвуют

По умолчанию — категория `MONSTER`, только записанное **естественное** появление (`NATURAL`).
Спавнеры, яйца, команды, рейды и остальные причины не дают зачистку и не подавляются.
Слизни, магмовые кубы, визер, дракон и варден исключены. Список ID редактируется в конфиге;
есть список дополнительных типов для нестандартных монстров из других модов.

Мобы, существовавшие до установки, не имеют происхождения и по умолчанию не дают прогресс.
`creditUnknownOrigins=true` позволяет учитывать их по месту смерти, но также разрешает
начисления за мобов с неизвестным происхождением от других модов. Известные неестественные
причины эта настройка не разрешает.

### Временная безопасность

- `100` временных очков отменяют все подходящие естественные попытки появления.
- `60` очков означают примерно 60% отменяемых попыток, а не строго 60% меньше мобов.
- Каждое начисление обновляет паузу перед убыванием, в том числе при полном счётчике.
- Пауза — **30 минут** активного серверного времени.
- После паузы теряется **1 очко за 5 минут**. Очки могут быть дробными.
- При отсутствии всех игроков, кроме наблюдателей, часы по умолчанию стоят.
- Отключённый сервер, сон и `/time set` не продвигают эти часы.
- AFK-игрок считается присутствующим. Один онлайн-игрок в любом измерении запускает
  общие часы для всего сервера. При низком TPS часы идут медленнее реального времени.

### Обжитость и постоянная безопасность

Бытовые блоки учитываются **после установки игроком**:

1. отдых — кровати;
2. хранение — сундуки и бочки;
3. работа — верстаки и печи, включая коптильню и плавильную печь;
4. очаг — костры.

Сгенерированные миром блоки не регистрируются автоматически. Для старых построек
администратор может посмотреть на блок и выполнить `/cleansing register`.

Ячейка с зарегистрированным бытовым блоком может быть центром участка пребывания.
В её окрестности 3 × 3 ячейки на той же высоте должны быть представлены минимум
**две разные категории**. Повторение одной категории не увеличивает обжитость.

- Игрок выбирает ближайший подходящий участок в радиусе 24 блоков от центра ячейки.
- Текущий участок удерживается до 28 блоков: шаг через внутреннюю границу не сбрасывает визит.
- Игрок должен оставаться в том же 8-блочном высотном слое. Переход на другой этаж
  завершает визит; это осознанное ограничение простой сетки.
- Первые **60 секунд** непрерывного посещения не учитываются.
- Затем накапливается освоение. Через **1800 секунд** учтённого присутствия участок обжит.
- Несколько игроков на одном участке не умножают скорость освоения.
- Взаимодействия с дверями, картами и сундуками специально не отслеживаются:
  они естественным образом увеличивают длительность визита.
- Обжитость участка относится к его 3 × 3 ячейкам на той же высоте.

Ячейка становится **навсегда безопасной**, когда набрала **200 постоянных очков**
и находится возле обжитого участка с действующей бытовой инфраструктурой.
Прогресс убийств может накопиться до обживания — закрепление произойдёт при освоении.
Разбор инфраструктуры после закрепления не отменяет постоянную защиту.
До закрепления обжитость не действует без достаточного числа категорий.
Если убрать все зарегистрированные блоки из ячейки-центра, её время освоения удаляется.

**Дорога без инфраструктуры не закрепляется навсегда**, даже после 200 убийств.
Счётчик прогресса при этом сохраняется. Если впоследствии там построить и освоить лагерь,
он сможет закрепиться. Одни только бытовые блоки не подавляют спавн.

## Уровни Святости и стол зачарования

Святость — одно зачарование с двумя уровнями. Уровень влияет только на горение нежити;
защиту от спавна дают оба уровня.

| Библиотека стола | Первая строка | Вторая строка | Третья строка |
|---|---|---|---|
| без полок и малая (до ~5 полок) | Святость I | Святость I | Святость I |
| средняя (~10 полок) | Святость I | Святость I | Святость II |
| полная (15 полок) | Святость I | Святость I | Святость II |

На наковальне: пустой баннер + баннер с чаром = тот же уровень за **2 уровня** опыта
(цвет, узоры и имя берутся от нового баннера), два баннера со Святостью I = «Святость II»
за **6 уровней**. Цены настраиваются параметрами `sanctityLevelOneCost` и
`sanctityLevelTwoCost`. Третьего уровня не существует: `/enchant @s settledlands:sanctity 3`
отклоняется.

## Дебаг и команды

Требуются права уровня **2** (обычно оператор сервера). Изменения админ-командами
относятся только к ячейке, в которой стоят ноги администратора.

| Команда | Действие |
|---|---|
| `/cleansing info` | Текущая ячейка, очки, обжитость и часы |
| `/cleansing stats` | Количество записей и отменённых попыток в измерении |
| `/cleansing debug on` | Подсветка для себя, радиус 32 блока |
| `/cleansing debug off` | Выключить подсветку |
| `/cleansing debug radius 64` | Радиус от 16 до 64 блоков |
| `/cleansing origin <entity>` | Записанное происхождение сущности, поддерживаются селекторы |
| `/cleansing register` | Зарегистрировать бытовой блок под прицелом, до 8 блоков |
| `/cleansing set <temporary> <progress>` | Задать оба счётчика текущей ячейки |
| `/cleansing permanent confirm` | Принудительно закрепить текущую ячейку |
| `/cleansing reset confirm` | Сбросить её зачистку и постоянный прогресс |

Пример: `/cleansing origin @e[type=minecraft:zombie,sort=nearest,limit=1]`.
`reset` не стирает бытовую инфраструктуру и время обживания.

`/cleansing ward` показывает источники Святости в текущей ячейке.

Подсветка рисует **рамки объёмов ячеек**, не заменяет воздух и не ставит сущности.
Цвет меняется от красного к зелёному по временной зачистке; голубой — постоянная безопасность; фиолетовый — защита Святости.
Надпись `T 73/100 | P 126/200 | H 64%` показывает временную зачистку, постоянный прогресс
и обжитость. Закреплённая ячейка подписана `PERMANENT`.

Данные идут только включившему дебаг администратору, раз в секунду, с ограничением
512 ячеек. Видны текущий высотный слой и по одному соседнему. Подписи рисуются не далее
48 блоков и ограничены 100 видимыми ячейками; рамки отсеиваются по полю зрения.
При потере обновлений изображение исчезает через 5 секунд. Без клиентского JAR работают
текстовые команды, но не рамки и подписи.

## Производительность и сохранение

- Никаких индивидуальных таймеров, потоков или фоновых задач на ячейку/моба.
- Убывание вычисляется по времени последнего изменения только при обращении.
- Спавн: фильтр причины/типа + поиск ячейки. Принудительное разрешение спавна не используется.
- Убийство: по умолчанию максимум 10 уникальных обновлений, без загрузки чанков источника.
- Посещение: раз в 20 тиков, поиск только ближайших ячеек бытовой инфраструктуры.
  Начало визита хранится как отметка времени. После задержки учтённые секунды фиксируются
  в памяти раз в секунду — это упрощает совместное присутствие и защиту от двойного начисления.
  **Это не запись файла каждую секунду.** Данные сохраняются через `SavedData` вместе с миром.
- Накопленное освоение сохраняется; незавершённая задержка визита после перезапуска начинается заново.
- Сломанные бытовые блоки удаляются событием. Дополнительно максимум 16 записей на измерение
  проверяются раз в секунду в циклическом порядке, только в уже загруженных чанках.
  Это ловит взрывы, поршни и сторонние изменения с возможной задержкой.
- Мод не сопровождает бытовые блоки при перемещении поршнем: на новом месте их нужно
  установить заново или зарегистрировать командой.
- Прогресс навсегда требует долговременного хранения: обнуление временных очков не удаляет
  постоянный счётчик. Полностью закреплённые ячейки хранятся как набор ключей.
- По умолчанию не более 250 000 ячеек и 100 000 бытовых блоков на измерение. При заполнении
  новые записи пропускаются, старые не теряются, в журнал идёт редкое предупреждение.
- Изменяемые записи хранятся в primitive-key map с объектами записей; фактическая память
  выше суммы числовых полей. Нагрузочные измерения на большом сервере пока не проведены.

Файлы: `data/settledlands_clock.dat` в обычном мире и `data/settledlands_territories.dat`
в каталоге данных каждого измерения. Формат данных имеет версию. Удаление мода не меняет
блоки мира; сохранённые данные остаются до ручного удаления.

## Сборка из исходников

Требуется **JDK 21**. Проверка и полный прогон:

```bash
CI=true ./gradlew build --no-daemon                 # сборка + unit-тесты
CI=true ./gradlew runServer -PsanctitySmoke --no-daemon   # интеграционные проверки
```

Перед запуском интеграционного набора скопируйте `smoke-server/server.properties`
в `run-smoke/server.properties`. Флаг `CI=true` отключает дорогую рекомпиляцию
исходников Minecraft и нужен на машинах с небольшим объёмом памяти.

Не задавайте `_JAVA_OPTIONS` с большим `-Xmx`: шаги сборки запускают дочерние JVM,
и на слабой машине они падают с «Failed to execute tool». Память Gradle настраивается
через `org.gradle.jvmargs` в `gradle.properties`. Первая сборка скачивает и готовит
артефакты Minecraft (около полуминуты, нужен интернет).


Нужны JDK 21 и интернет для Gradle/NeoForge/Minecraft-зависимостей.

Windows PowerShell:

```powershell
.\gradlew.bat build
```

Linux/macOS:

```sh
chmod +x gradlew
./gradlew build
```

JAR появится в `build/libs/settledlands-0.4.4.jar`.

Для быстрой сборки без декомпиляции Minecraft используйте поддерживаемый MDG режим CI:

```sh
CI=true ./gradlew build
```

PowerShell: `$env:CI='true'; .\gradlew.bat build`.
Это официальный бинарный pipeline ModDevGradle, а не подмена игровых классов.
Обычная первая сборка с исходниками Minecraft требует больше памяти (рекомендуется 4–6 ГБ).
`./gradlew runClient` / `./gradlew runServer` — запуск среды разработки.

## Ограничения альфы

- Это альфа, а не проверенный на публичном сервере релиз. См. `TESTING.md`.
- Реалистичный прогон базы, дороги, шахты и причала нужен для подбора чисел.
- Мобы заходят из соседних областей; запрета движения и защитных стен нет.
- Полная временная безопасность замедляет получение оставшихся 100 очков до закрепления:
  понадобятся пришедшие мобы либо повторная зачистка после убывания.
- Источники естественных мобоферм также подавляются. Фермы со спавнером не затрагиваются.
- Другой мод, обходящий стандартные события спавна/смерти, может не поддерживаться.
- Идентификация происхождения начинается при `FinalizeSpawnEvent`; специальные спавны,
  не проходящие стандартный `PositionCheck`, не являются целью подавления этой версии.
- Список бытовых категорий фиксирован в коде; поддерживаются наследники соответствующих
  классов блоков. Произвольные ID бытовых блоков и теги можно добавить в следующей версии.
- Нет AFK-детектора, карты территории, защиты от намеренного фарма прогресса или взаимодействия
  с системами приватов. AFK возле инфраструктуры позволяет освоить её, но не даёт очки убийств.
- Совместимость необязательного клиента предусмотрена в протоколе; реальное подключение
  обычного клиента и визуальный рендер нужно проверить вручную.

Короткое объяснение для игроков:
> Сражения делают места безопаснее. Обустройте лагерь и проводите там время, чтобы
> со временем закрепить безопасность навсегда. Необустроенные маршруты снова становятся опасными.
